# 构造审校案例

以下全部为构造例句，不是实际产品新闻；数字和事件仅用于演示，不能复制为新稿事实。

| 待审句 | 条件与改法 | 应保留的边界 |
|---|---|---|
| 上下文窗口像一次能摊开的材料。 | 先查产品文档，再用容量解释窗口，分清容量与材料本身 | 输入输出是否合计、实际限额由产品文档决定 |
| 智能体为什么会多次消耗？ | 先明确讨论的是调用次数、token用量、费用还是耗时 | 前文已有明确对象时省略可能成立 |
| 成本从100元降到50元，降低了一倍。 | 成本从100元降到50元，降低了50% | 先核对两值及计费范围 |
| 占比从20%升到30%，提高10%。 | 占比从20%升到30%，提高10个百分点 | 相对增幅为50%，不能与百分点混写 |
| 公司考虑裁员，因此岗位已经减少。 | 只写已证实的讨论状态，执行状态另核对 | 考虑不是准备实施，更不是已执行 |
| 价格下降了20%。这说明价格确实发生了下降的变化。 | 删除没有新增信息的第二句 | 若第二句补期限、税费或适用人群则应保留 |

## 正常反例

- 全班同学几乎全部到场。
- 不能否认公司没有按时交付。
- 模型第一层的参数已经冻结。
- 这项技术能够识别人类说话的声音。
- 只有一次失败，就让整个团队停止了测试。
- 智能体为什么会多次消耗输入token？
- 公司发布了一份题为《未来已来》的报告。

这些句子在相应语境下可以成立。它们帮助发现误判，并不为某项真实事件提供证据。
